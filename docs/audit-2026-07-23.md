## Critical Bugs (Installer Broken on Fresh Install)

### BUG-1: `sourcePath == installPath` — installer reads from empty destination

**Location:** `cmd/rama-installer/main.go:123-124`

```go
defaultSourcePath  = "/opt/searxng-rama"
defaultInstallPath = "/opt/searxng-rama"
```

**Introduced by:** commit `6850bcd` ("fix: update theme paths for installed structure")

**Impact:** On a fresh install, `/opt/searxng-rama` does not exist. The installer:
- `validateSource()` checks for `searx/`, `searx/static/`, `searx/templates/` under this path → all missing → **fatal error**
- `copySearxngFiles()` copies from a non-existent source → copies nothing
- `applyTheme()` reads theme `.less` files from this path → file not found → **fatal error**

The previous value was `/home/nomadx/searxng-custom` (a local SearXNG source checkout). The installer was designed to copy FROM a SearXNG source checkout TO the install destination. Making them the same path breaks this entirely.

**Severity:** BLOCKER — installer cannot run on any clean system

---

### BUG-2: `install.sh` never clones SearXNG

**Location:** `install.sh`

The install script:
1. Clones the RAMA installer repo (`searxng-RAMA`)
2. Builds the Go installer
3. Runs the installer

It does **not** clone the upstream SearXNG repository. The installer assumes `sourcePath` already contains a full SearXNG checkout with `searx/`, `searx/static/`, `searx/templates/`. The PKGBUILD workflow works because it clones SearXNG separately during `makepkg`; the `install.sh` workflow never did.

**Severity:** BLOCKER — the one-line installer (`curl | bash`) cannot work

---

### BUG-3: `theme/google/` is not committed to git

**Evidence:** `git ls-files theme/` returns only `theme/rama/definitions.less`

`theme/google/definitions.less` exists on disk but is untracked. Anyone cloning the repo will not get the Google theme. The `availableThemes` registry references it, but the file won't be present.

**Severity:** BLOCKER for Google theme selection

---

### BUG-4: Theme path mismatch between repo layout and installer expectations

**Location:** `cmd/rama-installer/main.go:644`

```go
sourceFile := filepath.Join(m.sourcePath, "searx", "static", "themes", "simple", "themes",
    selectedTheme.path, "definitions.less")
```

The installer reads themes from `searx/static/themes/simple/themes/{name}/definitions.less`, but the repo stores them at `theme/{name}/definitions.less`. Only the PKGBUILD bridges this gap by copying themes into the SearXNG tree during build (PKGBUILD lines 112-115). The installer itself never performs this copy.

**Severity:** BLOCKER — themes are never found by the installer

---

### BUG-5: `applyTheme` writes `.less` file to `css/` directory

**Location:** `cmd/rama-installer/main.go:645`

```go
destFile := filepath.Join(m.installPath, "searx", "static", "themes", "simple", "css", "definitions.less")
```

SearXNG's simple theme compiles Less from `src/less/`, not `css/`. Dropping a raw `.less` file into `css/` means either:
- The web server serves it as-is (uncompiled Less, not valid CSS)
- It's ignored entirely

The correct destination is `themes/simple/src/less/definitions.less` (where SearXNG's build expects it), or the theme should be applied as precompiled CSS.

**Severity:** MAJOR — even if themes are found, the CSS won't apply correctly

---

### BUG-6: `strings.Replace(..., 1)` misses repeated occurrences

**Location:** `cmd/rama-installer/main.go:437-445`

```go
themeStr = strings.Replace(themeStr, `:root.theme-auto`, `:root.theme-light`, 1)
themeStr = strings.Replace(themeStr, `@media (prefers-color-scheme: dark)`, `/* @media ... */`, 1)
```

In `theme/google/definitions.less`, `:root.theme-auto` appears **4 times** (lines 67, 137, 206, 214). Only the first occurrence is replaced. The remaining `.theme-auto` blocks leave conflicting light/dark CSS rules active.

**Fix:** Use `strings.ReplaceAll()` or loop with `strings.Replace(..., -1)`.

**Severity:** MAJOR — Google light/dark themes produce broken CSS

## Security Issues

### SEC-1: `.git` directory copied to installation

**Location:** `cmd/rama-installer/main.go:403`

```go
files := []string{"Makefile", "manage", "requirements.txt", "requirements-dev.txt", "setup.py", "babel.cfg", ".git"}
```

The entire `.git` directory (commit history, config, hooks) is copied to `/opt/searxng-rama/.git/`. If the service directory is ever web-accessible through misconfiguration, git history is exposed.

**Recommendation:** Remove `.git` from the copy list.

### SEC-2: `rm -rf` via exec instead of stdlib

**Location:** `cmd/rama-installer/main.go:535`

```go
exec.Command("rm", "-rf", m.installPath)
```

Uses `exec.Command` (no shell, so metacharacters aren't interpreted — low severity currently). If paths ever become user-supplied via CLI flags, this becomes a vector.

**Recommendation:** Use `os.RemoveAll(m.installPath)`.

## Moderate Issues

### MOD-1: Switch-theme mode depends on paths that are never created

**Location:** `cmd/rama-installer/main.go:193-200`

Switch-theme mode has 4 tasks: check privileges → stop service → applyTheme → start service. It skips all file-copying. But `applyTheme()` still reads from `m.sourcePath/searx/static/themes/simple/themes/...` — a path that:
- Wasn't created by the installer (theme files are in `theme/`, not `searx/static/themes/...`)
- Won't exist unless the PKGBUILD workflow pre-populated it

Even if a prior install happened via PKGBUILD, the installer never placed theme `.less` files at that path, so switch-theme has no source to read from.

### MOD-2: Switch-theme task naming is semantically wrong

**Location:** `cmd/rama-installer/main.go:197`

The "Start service" task uses `enableAndStartService()` which calls both `systemctl enable` and `systemctl start`. In switch-theme mode, enable is redundant (service is already enabled). Functionally harmless but semantically incorrect.

## Minor Issues

### MIN-1: `pip install` has no timeout

**Location:** `cmd/rama-installer/main.go:461-465`

If `pip` hangs due to network issues, the installer hangs indefinitely with a spinner and no indication of what's happening.

### MIN-2: `settings.yml` backups accumulate on reinstall

**Location:** `cmd/rama-installer/main.go:488`

```go
backupPath := settingsPath + ".bak." + fmt.Sprint(time.Now().Unix())
```

Every reinstall creates a new timestamped backup file. On repeated installs this fills disk with `.bak.1234567890` files.

**Recommendation:** Use a single `.bak` file or clean up old backups.

### MIN-3: Swallowed errors in `setPermissions`

**Location:** `cmd/rama-installer/main.go:475-478`

```go
if err != nil {
    return nil // User doesn't exist, skip
}
```

`id -u` can fail for reasons other than "user doesn't exist" (binary not in PATH, OOM). The error is swallowed and all permission-setting silently skipped.

### MIN-4: `.git` listed in `files` slice but treated as directory

**Location:** `cmd/rama-installer/main.go:403, 409-414`

`.git` is in the `files` slice but detected as a directory and copied via `copyDir`. Works, but the type categorization is confused.

## Root Cause Analysis

The multi-theme implementation (commits `3c61f55`–`32f505f`) was built and tested assuming the **PKGBUILD workflow**, where:
1. SearXNG is cloned separately
2. Themes are copied into the SearXNG source tree during build
3. Everything is packaged to `/opt/searxng-rama/`

Commit `6850bcd` then tried to adapt the installer to read from the *installed* structure (assuming PKGBUILD had already populated it). This broke the `install.sh` workflow, which:
1. Only clones the RAMA installer repo (not SearXNG)
2. Never copies themes into a SearXNG tree
3. Runs the installer with no source files available

The installer fundamentally needs a SearXNG source to copy from. The `install.sh` workflow never provides one.
